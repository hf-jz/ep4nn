## 横向三个结论

1. **接线问题基本解决，动力学与映射是瓶颈。** 数据从 302（线虫）→ 3,016（果蝇幼虫）→ 139,255（FAFB 雌性全脑）→ 166,691（MaleCNS 雄性全中枢，含腹神经索）已经到位，且 MaleCNS 是 CC-BY 4.0 可商用。但 8 个项目里**没有一个**能让"接线自己产出行为"：
   - 最严格的端到端尝试（therealfly）拿到的是**打乱接线同样复现的失控振荡**——这是整个生态里最强的负结果；
   - 其余项目全部在补同一层东西：**语义映射**（哪个群是什么感觉、哪个群驱动什么、什么参数、什么读出）。FlyDrones 自己把这条写在"the honest part"里，FlyBrain-HarmonyOS 叫它"混合驱动"。
   - 与 Cadence 线虫示例的判定完全一致：**接线是实测的，功能是映射层给的。**

2. **能跑 ≠ 有脑。** 名义规模与实际运行规模的差距是这个生态的常态：FlyDrones 的浏览器 demo 跑 850 神经元的 MiniFly；fruit-fly-brain 跑 LPLC2→DN 子图；flycoinrh 虽然真跑全图，但读出只有 4 个下行神经元、奖励是 novelty 替身；flybrain 的"涌现"由 50–80 个功能群 + 行为状态表承担。审阅时**先问"这条命令实际跑多少神经元、用什么参数"**，README 的数字几乎总是数据集的数字。

3. **实时性是工程件问题，不是理论问题。** 同一张 16.5 万神经元全图：HarmonyOS 手机 10 Hz 实时（CSR + 分块 + 群门控）、Cadence 在笔记本 CPU 上 4 ms/步（≈0.25 Hz 单步能力，settle 需要多步）、therealfly 用 torch 分块跑 1.7 s 脑时间 ×18 种子。控制回路要 20–100 Hz 时，"全图 LIF + 事件驱动 + 稀疏"是唯一现实路径。

## 方向讨论：四条候选路线

| 路线 | 内容 | 价值 | 风险 | 我的判断 |
|---|---|---|---|---|
| A 接线→行为端到端 | 照 therealfly 的纪律，把"该用什么驱动、在什么区间非失控、有没有节律"问到底（Pugliese 2025 的 DNg100/DNb08、驱动器强度、逐项神经元性质） | 科学价值最高；正负都值钱；一旦正结果就是"接线驱动身体"的第一份证据 | 周期长、结果不可控；需要算力与耐心的双投入 | **做，但只作为证据层**，不做主线 |
| B 接线约束的控制器 | 不追求"全部由接线产生"，而是把接线当**先验/骨架**，在它上面学读出与增益（Cadence fly lane 已证明：T-maze 双方向反转 0.17↔0.85；13 条生理事实通过 7、14 条本能事实通过 8，打乱接线只有 1–3） | 可交付、可量化、可复制到工业控制 | 容易被问"哪部分是脑做的"——必须像 FlyDrones 那样把边界写在第一屏 | **主线** |
| C 硬件/身体闭环 | 无人机（FlyDrones 已有 4 后端）或腿式（therealfly 已有 flybody + MuJoCo） | 差异化全在身体：真实延迟、磨损、噪声 | 硬件成本与失败公开化 | **与 B 合并执行**，身体是 B 的验收台 |
| D Web/agent/加密应用 | flycoinrh 那种"果蝇在互联网上走动" | 流量与传播 | 合规与信任风险；且 flycoinrh 自己承认奖励是 novelty 替身，学的是伪目标 | **不做** |

**我的主张**：主攻 B+C 的交叉，产出一个**可复现的"接线→身体"闭环基准台（harness）**，因为它是当前生态缺失的那一件公共品：

1. 8 个项目各自声明边界，口径互不可比。把 harness 定在同一个身体（`flybody`/MuJoCo）+ 同一个动力学（Shiu 2024 LIF）+ 同一套映射契约上，任何人（含我们自己）换接线、换驱动、换读出都必须出同一格式的收据。
2. 它直接回答 therealfly 卡住的问题（"接线在什么驱动下产生节律、非失控区间在哪"），而且**无论正负都能发布**——这正是 therealfly 已经证明有效的工作方式（协议先提交、只跑一次、不改常数）。
3. 一旦出现正结果，它就是"实测接线能驱动真实身体"的第一份可复现证据，商业价值天然（硬件+软件+数据飞轮）；没有正结果也有价值（把"缺的是模型、驱动还是映射"这三问分开回答，比各自猜要值钱）。
4. 技术上直接吃上一轮的实测结论：事件驱动稀疏 + 定点迭代加速 + **局部（活动集）收缩证书**——这三件是让 16.5 万神经元进入 20–100 Hz 控制回路的必要条件；Cadence 那边已经有可抄的契约（残差资格、拒绝语义、`preflight` 预检、`seam_report`）。

**不建议再做的事**：把"302 / 16.5 万神经元"当卖点的叙事；没有钱包隔离与合规设计的自主 web agent；以及在"接线能不能涌现行为"上用调参代替协议。

## 需要你定的三件事（会改变方案形态）

1. **目标是论文级证据还是产品级交付？** 前者按 therealfly 的协议纪律走（预注册、判决式报告、正负都发）；后者优先 B+C 的先跑通、再补证据。
2. **第一个受控任务选哪个？** 飞行（FlyDrones 的视觉光流→DNg02/DNp01 已有底盘与文献对照）还是腿式（therealfly 有身体、有映射、有已知失败）？飞行见效快、腿式的科学悬念大。
3. **算力边界在哪？** 全图 16.5 万 LIF 实时需要 GPU（therealfly 已用 torch 分块；Cadence 那边 150k 步 ≈4 ms 是 CPU 上限）。有没有可用 GPU 服务器，决定 harness 是"本机可复现的小子图 + 云端全图"还是"全图本地"。
